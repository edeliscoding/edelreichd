# Portfolio Development Skill

## Developer Profile

This portfolio belongs to an experienced web developer and Drupal developer.

The portfolio should present the developer as an established professional, **not as a beginner or entry-level developer**.

Professional background includes:

- Professional Drupal development
- Custom Drupal themes and modules
- Drupal Views, Twig, preprocess functions, render arrays, services, APIs, and integrations
- HTML5, CSS3, JavaScript
- React and Next.js
- Node.js
- PHP
- Python
- SQL and NoSQL
- REST APIs and JSON:API
- CMS development
- Web accessibility
- AI prompt engineering
- SaaS application development
- Modern responsive web development
- IT support and systems experience
- BS in Computer Information Systems
- CompTIA A+

The developer has built and worked on multiple professional and personal projects, including Drupal applications, SaaS applications, React/Next.js applications, API integrations, and custom CMS functionality.

The portfolio should communicate **depth and breadth of experience** without becoming a giant technology list.

# Core Portfolio Goal

The portfolio should answer these questions quickly:

1. Who is this developer?
2. What kind of development work does he do?
3. What technologies does he work with?
4. What professional projects has he built?
5. What Drupal expertise does he have?
6. What SaaS/web applications has he built?
7. What React/Next.js experience does he have?
8. How can someone contact or hire him?

The site should feel like the portfolio of an experienced developer who can work across **CMS development, full-stack web applications, frontend development, APIs, and modern web platforms**.

Do not make the site feel like a collection of beginner coding exercises.

# HTML

Use semantic HTML5:

- `header`
- `nav`
- `main`
- `section`
- `article`
- `aside` when appropriate
- `footer`

Keep the HTML:

- semantic
- accessible
- organized
- easy to maintain
- easy to understand

Use appropriate heading hierarchy.

There should be one clear `<h1>`.

Use meaningful link text.

Use buttons for actions and links for navigation.

Include appropriate:

- `aria-label`
- `aria-expanded`
- `aria-controls`
- semantic landmarks

when necessary.

Do not add ARIA attributes unnecessarily.

---

# CSS

Create a polished, modern developer portfolio that feels custom-designed.

Use:

- CSS custom properties
- Flexbox
- CSS Grid
- `clamp()` for responsive typography
- logical spacing
- responsive units
- media queries
- transitions
- subtle animations
- pseudo-elements when useful
- CSS state classes

Do not use framework classes.

Avoid generic "developer portfolio" styling.

Avoid excessive:

- gradients
- shadows
- rounded cards
- glassmorphism
- glowing effects
- oversized decorative shapes
- random floating elements
- unnecessary animations

The design should rely primarily on:

- typography
- spacing
- layout
- contrast
- hierarchy
- composition
- subtle motion

The site should feel sophisticated enough for a professional developer with several years of experience.

---

# Visual Direction

The visual identity should communicate:

**experienced developer + modern web + technical depth + clean design**

The design should not look like a template.

Avoid the common AI-generated portfolio appearance:

- giant centered heading
- random gradient blobs
- excessive glass cards
- identical project cards
- excessive pill-shaped badges
- meaningless statistics
- generic "passionate developer" copy
- huge technology logo walls
- excessive animations

Instead, create a strong visual system.

Use a limited color palette.

Establish:

- primary background
- secondary background
- text color
- muted text
- accent color
- border color

Use consistent spacing throughout the site.

Typography should be one of the strongest visual elements.

---

# JavaScript

Use plain JavaScript only.

Use:

- `querySelector`
- `querySelectorAll`
- `addEventListener`
- `classList`
- `dataset`
- DOM manipulation
- `IntersectionObserver`
- event delegation when appropriate
- CSS classes for animation states

Do not use jQuery.

Keep JavaScript in:

```text
js/script.js
```

Do not place large amounts of JavaScript directly inside `index.html`.

JavaScript should enhance the experience rather than control the entire site.

---

# Interactions

Implement subtle, professional interactions such as:

- mobile navigation menu
- navigation menu open/close state
- smooth scrolling
- active navigation state
- reveal-on-scroll animations
- project hover interactions
- project filtering if useful
- scroll-to-top button
- subtle link hover states
- accessible focus states
- navigation behavior based on scroll position

Animations should feel intentional.

Do not animate everything.

Respect:

```css
@media (prefers-reduced-motion: reduce);
```

When reduced motion is enabled, minimize or disable nonessential animations.

---

# Responsive Design

The portfolio must work beautifully at:

- 320px
- 375px
- 768px
- 1024px
- 1440px+
- large desktop displays

Design mobile intentionally.

Do not simply shrink the desktop layout.

Pay particular attention to:

- navigation
- hero typography
- project layouts
- technology lists
- experience timeline
- spacing
- buttons
- contact section
- long project descriptions

Avoid horizontal overflow at all viewport sizes.

# Important Development Principles

## Do not over-engineer

This portfolio is intentionally built with HTML, CSS, and vanilla JavaScript.

Do not recreate a React application architecture in vanilla JavaScript.

Keep the implementation straightforward.

## Do not rewrite working code unnecessarily

If existing code works correctly, preserve it unless there is a clear reason to change it.

Improve incrementally.

## Do not invent professional experience

Never invent:

- projects
- employers
- job responsibilities
- technologies
- metrics
- clients
- accomplishments
- certifications

If information about a project is missing, leave a clearly identifiable placeholder or ask for the information.

## Do not reduce the developer to a technology list

The portfolio should demonstrate **what the developer has built and the problems he can solve**, not simply display technology names.

## Prioritize real projects

Professional and substantial personal projects should receive more attention than small experiments.

## Make the portfolio feel authored

The finished site should feel like a developer deliberately designed his own professional presence.

It should not feel like:

- an AI-generated template
- a bootcamp portfolio
- a generic SaaS landing page
- a collection of component examples

The goal is a **distinctive, technically credible, professional developer portfolio**.
